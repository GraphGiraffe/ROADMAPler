# История изменений

## 30.10.2026 — цвет системной строки

- Цвет строки состояния браузера/PWA синхронизируется с выбранной темой приложения при переключении и повторном открытии. Раньше `theme-color` всегда оставался светлым.


## 29.10.2026 — выбор версии при конфликте

- В окне конфликта слева «Мои», справа «Облако»; под каждым вариантом показано краткое описание изменений относительно общей версии. Отдельная кнопка «Оба» принимает облако и сохраняет локальные изменения копией.
- Сохранены проверка ревизии и защита от изменения проекта во время выбора.
- Владелец подтвердил синхронизацию ПК и телефона, разрешение конфликтов и регистрацию с подтверждением почты. Эти проверки закрыты на доске.

## 28.10.2026 — понятные действия аккаунта

- Смена пароля и восстановление по почте вынесены из скрываемой формы входа в отдельный раздел окна аккаунта. Вошедший пользователь видит оба действия; для восстановления подставляется почта текущего аккаунта.
- Синхронизация сгруппирована отдельно. Прежняя кнопка «Локальный режим» переименована в «Выйти из аккаунта»/«Отключить GitHub» и требует встроенного подтверждения; проекты сохраняются. Локальный режим проекта по-прежнему выбирается в его настройках.
- Прямая смена пароля не завершает текущее подключение. Подтверждённый выход очищает подключение, завершает сессию этого устройства и не отменяется поздним результатом refresh.

## 28.10.2026 — структура и большие доски

- Шаблон HTML, CSS и восемь исходных единиц разделены по ответственности. Сборка сохраняет один classic script/автономный HTML и не публикует исходные части вторым набором ресурсов.
- Поиск группирует ввод и не сериализует библиотеку ради обновления облачных значков. Настройки вида сгруппированы и сохраняются отдельным ключом на проект; старые данные миграции не удаляются, очередь сбрасывается перед закрытием и обновлением.
- Web Locks выделяет одного владельца записи библиотеки на путь приложения. Остальные табы доступны для просмотра и экспорта; старый снимок не получает права перезаписи после передачи владения без reload. Облачные запросы также проверяют владение после ожиданий.
- При неподдерживаемой безопасной блокировке сохранение модели не выполняется; данные доступны для экспорта. Старые вкладки прежней версии перед обновлением нужно закрыть. IndexedDB не вводился.
- Добавлены измерения 200/1000 карточек и локальные проверки двух вкладок. Для владельца подготовлены инструкции Supabase/почты/синхронизации и приёмки плагина в docs/RELEASE-ACCEPTANCE.md.

## 28.10.2026 — восстановление пароля

- В обычном аккаунте добавлены «Забыли пароль?», запрос письма и встроенная форма нового пароля с повтором.
- Сессия восстановления изолирована от проектов и сохранённого подключения: токены удаляются из URL до запроса, не сохраняются в хранилищах; временная сессия завершается при закрытии/успехе. Ошибочные ссылки, сбои и поздние ответы обрабатываются внутри приложения.
- Модуль включён в офлайн-оболочку PWA и исключён из автономного HTML. Локальные браузерные проверки не отправляют настоящую почту. Для живой приёмки нужно проверить Redirect URLs и SMTP Supabase.

## 28.10.2026 — плагин для агентов

- Добавлен локальный пакет Agent Plugins 1.0 с совместимостью Codex: три скилла и 18 MCP stdio-инструментов, работающих через общий CLI. Node.js 22+, без npm-зависимостей; credentials хранятся отдельно.
- В Интеграциях доступны скачивание ZIP и инструкция; открытый GET manifest API позволяет агенту узнать версию, скачать пакет и сверить размер/SHA-256. Архив генерируется воспроизводимо, содержит только разрешённые файлы и лицензии.
- Сохранены expected revision, точечные запросы, подтверждение удаления и отсутствие автоматических повторов при конфликтах. CLI и MCP скрывают токен в серверных ответах.
- Добавлены локальные проверки чистой распаковки/запуска MCP, всех инструментов, API-отказов и web-скачивания. `npm start` теперь собирает сайт перед предпросмотром, чтобы discovery API был доступен локально.

## 28.10.2026 — общий серверный helper токенов

- Полный и точечный API используют одну закрытую проверку токена, срока, отзыва, проекта и прав read/write/delete. Сигнатуры RPC и общий механизм записи с ревизиями сохранены.
- Добавлены локальные проверки PostgreSQL под ролями anon/authenticated, включая обновление старой установки и запрет прямого доступа к helper. Для применения на сервере требуется повторить `server/integrations.sql`.

## 28.10.2026 — очистка просмотра карточек

- Удалены недостижимое окно просмотра карточки, его обработчики и отдельный стиль. Карточки по-прежнему открываются сразу в редакторе. Архивы сохранены.

## 28.10.2026 — ограниченная история отмены

- История на проект ограничена 50 шагами и 2 МиБ снимков; единые правила действуют для обычных команд, импорта и облачных замен. Данные проектов не сокращаются.
- Контрольная точка PWA использует общий бюджет истории 2 МиБ, отдаёт приоритет активному проекту и не дублирует его undo/redo. При ошибке квоты обновление блокируется, текущая работа сохраняется.
- Модуль истории используется в web, PWA и автономном HTML; добавлены локальные проверки ротации, undo/redo, нескольких проектов и ошибок хранилища.

## 28.10.2026 — надёжность импорта и контракт формата

- Импорт обновления сохраняет облачную привязку, ревизию, базовую копию и дополнительные метаданные существующего проекта; отдельная импортированная копия остаётся локальной.
- Некорректная старая библиотека не перезаписывается; её исходные данные можно скачать целиком для восстановления.
- Проверка формата вынесена в самостоятельный модуль; типы и названия сущностей, уникальность ID и зарезервированные релизы проверяются до изменения проекта. Общие фикстуры согласуют JavaScript и PostgreSQL.
- Добавлены собственные локальные команды тестов, фиксированная dev-зависимость браузерного драйвера и lockfile. Набор проверяет импорт, отмену/повтор, ошибку записи, переносимый HTML и офлайн-PWA. Приложение не получило npm-зависимостей времени выполнения; Actions по-прежнему только build/deploy.
- Актуализированы README, архитектура, план и границы проверки интеграций; исторические заметки выпусков сохранены.

## 28.10.2026 — облачные значки на ПК

- Текстовые символы облака заменены минималистичными SVG с фиксированными размерами в шапке и вкладках проектов. Значки центрируются независимо от шрифта.
- Между названием проекта и облаком задан постоянный зазор; длинное название сокращается, сохраняя видимость значка.

## 28.10.2026 — порядок вкладок проектов

- В настройках и при создании проекта доступна позиция вкладки. Порядок сохраняется между запусками web/PWA.
- Изменение порядка и названия сохраняется одной командой с отменой/повтором, в том числе после применения обновления PWA. Восстановление порядка сохраняет добавленные позже проекты и не восстанавливает удалённые.

## 28.10.2026 — точечный API и настройки вида

- Добавлены серверные RPC и команды CLI для чтения, создания, изменения и удаления карточек, треков и релизов по ID. Поддержаны порядок колонок, поиск с фильтрами и пагинацией, дописывание комментария и компактная разница после ревизии. Все записи сохраняют общую защиту от конфликтов; удаление трека/релиза с карточками требует явной стратегии. Для новых RPC нужно применить `server/integration-api.sql` на Supabase.
- Каждый проект локально помнит видимость backlog, скрытые треки и релизы, выполненные карточки и релизы, фильтр и поиск между запусками web/PWA. Настройки не включаются в экспорт данных и не меняют облачный проект.
- В редакторах карточки, трека и релиза иконки сохранения, отмены и удаления закреплены в шапке, содержимое прокручивается отдельно. Статус поднят под название, комментарий — под описание, параметры размещения сгруппированы в две колонки с одинаковыми небольшими отступами.
- Исправлено постоянное сообщение о восстановлении проектов после PWA-обновления: автоскрытие запускается и для сообщения, установленного до подключения наблюдателя.

## 28.10.2026 — удаление и перенос карточек

- Иконки кнопок выровнены по центру на телефоне и компьютере; ручка диапазона помещается в компактную карточку.
- В редактор карточки добавлена кнопка удаления с подтверждением.
- При удалении трека или релиза можно удалить затронутые карточки либо перенести их в выбранные трек и релиз, включая новый трек в backlog. Диалог предупреждает о карточках на несколько релизов.
- Перенос сохраняет статусы и содержимое карточек, отменяется одним действием. При удалении последнего трека без переноса остаётся пустой новый трек.

## 27.10.2026 — уведомление об актуальной версии

- Сообщение об актуальной версии показывается поверх интерфейса сверху, не сдвигает доску, закрывается тапом или автоматически через пять секунд. Кнопка применения доступного обновления остаётся постоянной и требует явного действия.

## integrations-2026-10-27 — токены интеграций

- Добавлены серверная проверка SHA-256, общая CAS-запись и валидация проекта, интерфейс интеграций и CLI с защищённым файлом подключения. SQL-миграция владельцем применена; новые RPC и неавторизованный доступ проверены. Полный внешний сценарий ожидает тестовый scoped-токен.
