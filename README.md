# RADMAPler

Наработки отдельного приложения для планирования любых проектов: треки, релизы, карточки и backlog. Исходный прототип вырос из роадмапа PlayRoom; данные конкретного проекта отделены от сайта.

## Что открыть

- `public/index.html` — исходник автономного прототипа с пустым проектом. Уже работают карточки с описаниями, треки, релизы, backlog, перенос, отмена/повтор, светлая/тёмная тема, импорт/экспорт JSON и сохранение HTML.
- `projects/playroom.roadmap.json` — отдельный проект PlayRoom: 65 карточек, 12 треков. Его можно импортировать кнопкой «Импорт JSON». В сайт эти данные не встроены.
- `archive/prototypes/` — сохранённые предыдущие HTML с данными PlayRoom; `archive/previews/` — снимки предыдущих версий. Это история разработки, не публикация.

Репозиторий: [GraphGiraffe/ROADMAPler](https://github.com/GraphGiraffe/ROADMAPler). Сайт: [RADMAPler](https://graphgiraffe.github.io/ROADMAPler/).

GitHub Pages публикует **только `site/`**. Корень, `projects/` и `archive/` не являются веб-дистрибутивом; они сохраняются в репозитории как исходники и история разработки.

Приложение устанавливается как PWA и после первого открытия работает без сети. Проекты переключаются вкладками и сохраняются локально в браузере. Названия проектов, треков, релизов и карточек открывают редактирование по нажатию; настройки находятся в диалогах приложения. В ячейках доски есть кнопки создания карточек, а в самой таблице — добавление и скрытие треков и релизов.

Меню `⋯` содержит установку, проверку обновлений, импорт и экспорт. Смена темы находится справа в шапке. Для PWA нужен HTTPS или localhost; скачанный HTML остаётся автономной копией без установки и внешних ресурсов.

Карточку можно растянуть за правый край на несколько релизов или выбрать начало и конец в её настройках. Клавиши ←/→ на рукоятке изменяют конец диапазона. Пересекающиеся карточки располагаются на разных строках внутри трека. Все изменения поддерживают отмену и повтор.

В настройках релиза и backlog выбирается статус по умолчанию: он применяется при переносе в колонку и подставляется для новой карточки. Цвет и иконка в заголовке показывают это правило. Вариант «Не менять статус» оставляет колонку нейтральной. Диапазоны и правила колонок экспортируются в формате проекта версии 2; файлы версии 1 продолжают импортироваться.

## Структура и локальный запуск

Структура следует PECSoteka; имя папки публикации `site/` сохранено по правилам этого проекта.

| Путь | Назначение |
|---|---|
| `public/` | Исходники статического приложения |
| `scripts/` | Команды сборки |
| `site/` | Генерируемая веб-сборка; не коммитится |
| `docs/` | План продукта, архитектура и формат данных |
| `projects/` | Отдельные импортируемые проекты |
| `archive/` | Прототипы и изображения прошлых вариантов |
| `.github/workflows/` | Ручная публикация Pages |
| `CHANGELOG.md` | История изменений |

Нужен Node.js 22+; для локального HTTP-сервера — Python 3. Внешних npm-зависимостей нет.

```sh
npm start       # http://127.0.0.1:4173, исходники public/
npm run build   # готовый сайт в site/
```

Править нужно `public/`: сборка полностью пересоздаёт `site/` и вычисляет ревизию Service Worker по содержимому исходников. Автоматического набора тестов в репозитории пока нет; браузерные проверки выполняются локально. Основная модель и интерфейс пока находятся в `public/index.html`, установка и обновления — в `public/pwa.js`, офлайн-оболочка — в `public/sw.js`.

## Данные и обновления

Хранилище проектов — версионированная запись `localStorage`, отдельная для пути приложения. Это промежуточное решение до IndexedDB: объём ограничен квотой браузера. При ошибке записи изменение откатывается, форма остаётся открытой; при конфликте с другой вкладкой приложение не перезаписывает чужую запись. Неподдерживаемый формат хранилища не изменяется.

История отмены, фильтры и скрытые строки/колонки разделены по проектам в текущем сеансе. Перед явным применением обновления состояние сеанса сохраняется в `sessionStorage` текущей вкладки и восстанавливается после перезагрузки. Открытая форма, незавершённый импорт или ошибка сохранения откладывают обновление. Другие вкладки автоматически не перезагружаются.

Новая версия сначала загружает собственный кеш и ждёт кнопки **Обновить и продолжить**. Кеши и данные других приложений на том же домене не затрагиваются. Установка средствами конкретного телефона зависит от браузера; кнопка показывает доступный способ установки.

Экспортируйте JSON или HTML для резервной копии: очистка данных браузера удаляет локальные проекты. Markdown, архив всех проектов, автоматические резервные копии и миграция в IndexedDB пока не реализованы.

## Git и публикация

Как в PECSoteka: `main` — стабильная ветка, `dev` — интеграция. Изменения проходят через task-ветку и PR в `dev` (squash); публикация — после отдельного PR `dev` → `main` (squash). Первый коммит создаёт исходную историю пустого репозитория.

Публикация запускается вручную: Actions → **Publish Pages** → Run workflow на `main`, поле `ref` — точный проверенный SHA коммита `main`. Workflow выполняет `npm run build` и загружает только `site/` без установки зависимостей. На push и PR автоматических запусков нет; тестов и Chromium в Actions нет.

После завершения проверить успешный deploy и совпадение опубликованного `index.html` со сборкой из `public/index.html` выбранного коммита. Push сам по себе сайт не обновляет.
