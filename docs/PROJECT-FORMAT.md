# Переносимый проект · версии 1 и 2

Расширение: `.roadmap.json`. UTF-8, один проект в файле. Примеры с реальными данными — `projects/playroom.roadmap.json` и `projects/ROADMAPler.roadmap.json`, вне публикуемой папки сайта. Второй файл содержит семь предыдущих публикаций приложения, их состав и промежуточные патчи со ссылками на источники. Номерные версии не выдумываются: выпуски отмечены SHA стабильных коммитов и временем успешного Pages workflow.

```json
{
  "format": "roadmap-project",
  "formatVersion": 1,
  "schema": 2,
  "project": {"id": "example", "name": "Пример", "description": "", "updatedAt": "2026-10-27"},
  "tracks": [{"id": "product", "title": "Продукт", "subtitle": ""}],
  "releases": [],
  "tasks": [],
  "sources": []
}
```

`schema: 2` унаследовано от прототипа доски. Версия переносимого файла задаётся `formatVersion`; будущая миграция не должна угадывать её по приложению.

Версия 1 продолжает импортироваться. Диапазоны релизов и статусы колонок используют `formatVersion: 2`: при первом таком изменении проект переводится в версию 2. Раннее приложение отвергнет этот файл до изменения своего проекта. Неизвестная будущая версия также отвергается.

Карточка содержит `id`, `track`, `release`, `title`, `description`, `status`, `accept`, `source` и необязательный `comment`. Релиз задаётся ID из `releases`, либо строкой `backlog`. Статусы: `idea` (идея), `check` (нужно проверить), `planned` (запланировано), `work` (в работе), `done` (выполнено), `blocked` (заблокировано), `paused` (на паузе). При переносе статус меняется только по правилу целевой колонки. Неизвестный статус отвергается до изменения проекта; ранние версии приложения могут отвергать новые статусы `blocked`/`paused`.

В версии 2 необязательный `releaseEnd` задаёт последний релиз диапазона включительно; `release` — первый. Обе границы должны существовать, конец не может предшествовать началу. Backlog не участвует в диапазонах. Это одна карточка с одним ID и общим статусом. Без `releaseEnd` карточка занимает одну колонку.

Релиз версии 2 может содержать `defaultStatus`; корень проекта — `backlogDefaultStatus`. Значения берутся из того же списка статусов. Отсутствие поля означает «Не менять статус». При переносе применяется значение колонки начала нового диапазона; при создании оно подставляется в форму и может быть изменено. Растягивание границы само по себе статус не меняет.

Трек: `id/title/subtitle`. Релиз: `id/title/note/locked`. Источник: `id/title/path`. Источники и связь карточки `source` сохранены как совместимые метаданные: приложение не отображает и не редактирует их, но сохраняет при импорте, синхронизации и экспорте. Импорт не читает локальные файлы по `path`. Поле `comment` остаётся обычным комментарием пользователя.

Порядок массивов сейчас определяет порядок треков, релизов и карточек. Backlog не является записью релиза, всегда отображается справа. Ссылки карточек должны указывать на существующие треки/релизы, ID должны быть уникальны в своих коллекциях. При перестановке релизов границы диапазонов нормализуются по новому порядку. При удалении релиза пользователь выбирает удаление или перенос всех карточек, пересекающих релиз, включая целые диапазоны. Перенос в конкретный релиз или backlog сбрасывает `releaseEnd`; перенос в другой трек с сохранением текущих релизов оставляет диапазон. Перенос в диалоге удаления сохраняет статус независимо от правила целевой колонки. Перенос диапазона сохраняет его длину, насколько позволяет число оставшихся релизов.

Приложение проверяет тип файла, версию, основные списки, ID и связи карточек. Для полноценного приложения нужны полная схема, лимиты размера/строк, проверка всех вложенных полей и импорт с выбором политики конфликтов. Импорт по подтверждению создаёт отдельный проект или обновляет совпавший по названию с возможностью отмены; при нескольких совпадениях можно выбрать цель. Другие проекты сохраняются. Слияние и экспорт всей библиотеки пока не реализованы.

Локальная библиотека хранится отдельно от переносимого проекта: оболочка `{version: 1, active, projects: [{id, data}]}`. `id` записи библиотеки определяет вкладку, а `data` содержит переносимый проект без потери дополнительных полей. Версия библиотеки не является `formatVersion` импортируемого файла.
