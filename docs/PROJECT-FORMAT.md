# Переносимый проект · версия 1

Расширение: `.roadmap.json`. UTF-8, один проект в файле. Пример с реальными данными — `projects/playroom.roadmap.json`, вне публикуемой папки сайта.

```json
{
  "format": "roadmap-project",
  "formatVersion": 1,
  "schema": 2,
  "project": {"id": "example", "name": "Пример", "description": "", "updatedAt": "2026-10-27"},
  "tracks": [{"id": "product", "title": "Продукт", "subtitle": ""}],
  "releases": [],
  "tasks": [],
  "sources": []
}
```

`schema: 2` унаследовано от прототипа доски. Версия переносимого файла задаётся `formatVersion`; будущая миграция не должна угадывать её по приложению.

Карточка содержит `id`, `track`, `release`, `title`, `description`, `status`, `accept`, `source` и необязательный `comment`. Релиз задаётся ID из `releases`, либо строкой `backlog`. Статусы прототипа: `idea`, `check`, `planned`, `work`, `done`. `done` сейчас означает завершённость; более точный контракт выполненности и прогресса нужно закрепить до основной реализации.

Трек: `id/title/subtitle`. Релиз: `id/title/note/locked`. Источник: `id/title/path`. Путь источника — текстовая ссылка на происхождение идеи; импорт не читает локальные файлы по этому пути.

Порядок массивов сейчас определяет порядок треков, релизов и карточек. Backlog не является записью релиза, всегда отображается справа. Ссылки карточек должны указывать на существующие треки/релизы, ID должны быть уникальны в своих коллекциях.

Прототип проверяет тип файла, версию, основные списки, ID и связи карточек. Для полноценного приложения нужны полная схема, лимиты размера/строк, проверка всех вложенных полей и атомарный импорт с выбором политики конфликтов. Текущий импорт заменяет активное состояние с возможностью отмены; слияние и библиотека нескольких проектов ещё не реализованы.
