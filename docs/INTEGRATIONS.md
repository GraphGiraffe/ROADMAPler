# Токены интеграций ROADMAPler

Патч `integrations-2026-10-27`: владелец применил миграцию на действующем Supabase. Проверены наличие RPC, отказ без токена, запрет анонимного управления и CORS. Первая версия работает с облачными проектами обычного аккаунта Supabase. Локальные проекты и личный GitHub этим API не обслуживаются.

## Настройка сервера владельцем

В SQL Editor того же проекта Supabase выполнить по порядку:

1. Текущий `server/supabase.sql`: существующие таблицы и данные сохраняются, общий механизм записи выделяется в закрытую серверную функцию. Обычная синхронизация сохраняет прежний API.
2. `server/integrations.sql`: создаются закрытая таблица токенов, общий helper авторизации и серверные RPC. Helper проверяет read/write/delete для всех интеграционных запросов; удаление карточки/трека/релиза по-прежнему требует write, отдельное delete разрешает удаление целого проекта.
3. `server/integration-api.sql`: точечные операции с карточками, треками и релизами, поиск, комментарии и изменения после ревизии. Подробности и CLI: [точечный API](INTEGRATIONS-COMPACT.md).

Все три файла допускают повторное применение. Требуются права владельца SQL Editor; публичный ключ приложения не может создавать серверные функции. Административные ключи и пароль владельца не нужно передавать агенту. Для обновления существующей установки до общего helper достаточно повторить текущий `server/integrations.sql`; сигнатуры, токены, данные и ревизии сохраняются. Готовый файл этого обновления: `tmp_files/ROADMAPler-integration-auth-update.sql`. Владелец подтвердил применение SQL-обновления 28.10.2026; отдельная проверка настоящего письма/двух устройств остаётся открытой. Полный и точечный API продолжают работать с прежней серверной версией до применения.

Edge Function не требуется: проверка токена выполняется PostgreSQL-функцией в Supabase. Новые RPC, доступные роли anon, не дают читать таблицы напрямую и требуют отдельный действующий токен интеграции. Общая запись проекта остаётся закрытой функцией, доступной только проверяющим серверным обёрткам. Контекст аккаунта не подменяется токеном.

## Создание и отзыв

После публикации патча: меню приложения → **Интеграции**.

- Войти в обычный аккаунт ROADMAPler.
- Выбрать проект с включённой облачной синхронизацией; первая отправка проекта должна завершиться.
- Задать название, например «Помощник для проекта».
- Выбрать права: чтение, изменение, отдельно удаление проекта. По умолчанию включено только чтение.
- Выбрать срок: 7, 30, 90 или 365 дней. Сервер не принимает срок больше года.
- Создать токен и сохранить секрет либо скачать файл подключения. Закрытие окна, включая Escape, очищает секрет; повторного просмотра нет.

Список показывает проект, название, короткий префикс, права, срок, отзыв и время последнего **успешного** запроса. Хеш и полный секрет в списке отсутствуют. Отзыв требует подтверждения в приложении и блокирует последующие запросы. Уже исполняющийся запрос может завершиться до отзыва; операции согласованы блокировкой токена.

Лимиты: 100 действующих токенов и 1000 записей истории токенов на аккаунт. Для очистки истории после достижения лимита нужен владелец сервера; автоматическое удаление записей аудита не выполняется.

## Файл подключения

Скачанный JSON содержит `supabaseUrl`, публичный `publishableKey`, секретный `token` и облачный `projectId`. Это отдельный файл, не переносимый проект `.roadmap.json`.

На Linux/macOS, пример для скачанного файла:

```sh
install -d -m 700 ~/.config/roadmapler
install -m 600 ~/Downloads/ROADMAPler-credentials.json ~/.config/roadmapler/credentials.json
```

Удалите оставшуюся копию из Downloads после проверки. Сам токен не отправляйте в чат и не коммитьте. Для работы агента достаточно пути к защищённому файлу и ID проекта. По умолчанию CLI читает `~/.config/roadmapler/credentials.json`; другой путь задаётся через `--credentials`.

CLI на Unix отвергает символьные ссылки, файлы другого владельца и доступ группы/остальных. Права `600` или более строгие допустимы. На Windows требуется отдельно ограничить доступ средствами ОС; проверка POSIX-прав там не выполняется.

## Чтение и изменение

Нужен Node.js 22+. Никаких npm-зависимостей или административного ключа.

```sh
node scripts/integration-client.mjs read --out /tmp/roadmap-snapshot.json
```

Ответ — снимок `{id, revision, data, deleted, updated_at}`. Поле `data` содержит переносимый проект. Сохраните `id` и `revision`, измените нужные части `data`, затем:

```sh
node scripts/integration-client.mjs write --file /tmp/roadmap-snapshot.json
```

Версия берётся из снимка. Для обычного `.roadmap.json` без оболочки нужна явная `--expected VERSION`. Если другой клиент уже изменил проект, сервер вернёт HTTP 409: нужно прочитать новую версию и согласовать изменения. CLI не повторяет конфликтующую запись автоматически и не увеличивает ожидаемую версию сам.

Флаг `--project UUID` явно выбирает проект, но не расширяет право токена. `--out` создаёт новый файл с закрытыми правами и не перезаписывает существующий файл. Без него результат выводится в stdout; токен в вывод не попадает.

Удаление — отдельная операция и отдельное право:

```sh
node scripts/integration-client.mjs delete --expected VERSION --confirm-delete PROJECT_UUID
```

Удаление создаёт облачную отметку удаления и сохраняет историю, как обычное приложение. Изменением нельзя восстановить уже удалённый проект через интеграционный токен: это действие владельца в приложении.

## HTTP API

Endpoint: `POST <supabaseUrl>/rest/v1/rpc/roadmap_integration_access`.

Заголовки:

- `apikey`: публичный publishable/anon key проекта Supabase;
- `X-ROADMAPler-Token`: секрет интеграции;
- `Content-Type: application/json`.

Секрет не передаётся в URL, JSON проекта, параметры CLI или вместо JWT аккаунта. Для внешнего сервера нужен HTTPS. Клиент запрещает HTTP-перенаправления с учётными данными.

Тело:

```json
{
  "p_project_id": "UUID облачного проекта",
  "p_action": "read",
  "p_expected": null,
  "p_data": null
}
```

Действия: `read`, `write`, `delete`. Для записи и удаления `p_expected` обязателен. Для записи `p_data` — полный переносимый проект. Ответ RPC — массив с одним снимком; CLI снимает внешнюю оболочку массива.

Статусы: 400 — неверный запрос/формат, 401 — неверный, отозванный или истёкший токен, 403 — другой проект или недостаточно прав, 409 — конфликт версий, 410 — попытка изменения удалённого проекта, 413 — превышение квоты. Сервер использует общую валидацию проекта и общий механизм версии/истории для UI и интеграций.

## Хранение и границы

Сервер генерирует секрет из двух криптографических UUID (244 случайных бита) и сохраняет только SHA-256 и короткий префикс. Секрет возвращается только в ответе создания. Его нет в таблице, списке, библиотеке проектов, browser storage и JSON/HTML-экспорте приложения. Браузер показывает его только в текущем окне, но копирование или скачивание пользователем создаёт отдельную копию, которую нужно защищать самостоятельно.

Разрешение изменения даёт право менять всё содержимое выбранного проекта, включая карточки и релизы. Отдельное право удаления относится к удалению самого проекта; это не защита отдельных карточек от редактирования.

Прямой доступ к закрытой таблице токенов и общему серверному механизму записи запрещён. Именованные функции управления доступны только аккаунту-владельцу. OAuth и публичное подключение сторонних приложений в эту версию не входят.

## Плагин агентов и API скачивания

Раздел Интеграции предлагает ZIP плагина без входа в аккаунт; файл подключения скачивается отдельно после создания токена. Публичный GET `api/agent-plugin/manifest.json` относительно корня приложения возвращает schemaVersion=1, version, compatibility и archive={url,bytes,sha256}. URL архива разрешается относительно URL manifest; сравните размер и SHA-256 до распаковки. Инструкция находится рядом: `api/agent-plugin/README.txt`. Ни токен, ни проекты не передаются этому API. После установки вызовы проекта требуют защищённого credentials-файла и обычных прав scoped API.

Пакет содержит переносимые `plugin.json`/`mcp.json` и совместимые `.codex-plugin/plugin.json`/`.mcp.json`. В клиенте без импорта пакета можно отдельно зарегистрировать локальный MCP и подключить скиллы; подробности в [README пакета](../agent-plugin/README.md). Установка на компьютер владельца не выполняется автоматически. В офлайне discovery сообщает об ошибке с повтором; пакет не входит в обязательный PWA-кеш оболочки. Экспортированный автономный HTML, как и прежде, не включает облачный интерфейс.

## API 1.1: оформление треков и версии

`roadmap_integration_capabilities(p_project_id uuid)` требует тот же read-токен проекта и сообщает версию/возможности. Статический каталог `api/capabilities.json` публикуется без пользовательских данных. `roadmap_integration_structure` create/update tracks принимает optional icon (slug до 40 символов) и color (#RRGGBB); null удаляет поле. CAS по p_expected сохранён. API major 1 совместим с прежними клиентами; optional поля модели не требуют нового formatVersion.

Обновление базы: `server/track-appearance-update.sql` меняет только validator, structure RPC и добавляет capability RPC с явными grant/revoke. Пользовательские строки, RLS и токены не меняются. Плагин 0.2.0 предоставляет roadmap_capabilities, roadmap_plugin_status и roadmap_plugin_update; подробности в agent-plugin/README.md. Повторная установка больше не нужна после перехода на клиент с updater, но для загрузки нового кода нужно перезапустить MCP. Никаких фоновых опросов логов или автоматического обновления исполняемого кода.

Bootstrap для 0.1.0 без повторной установки: из официального `api/agent-plugin/manifest.json` получить `bootstrap.url` относительно manifest, проверить размер и SHA-256 файла по `bootstrap.bytes/sha256`. После явного поручения на обновление выполнить `node update.mjs --check ПАПКА_УСТАНОВЛЕННОГО_ПЛАГИНА`, затем `node update.mjs --apply ПАПКА_УСТАНОВЛЕННОГО_ПЛАГИНА`. Путь должен указывать на корень ROADMAPler с plugin.json, а не на credentials или родительский каталог кеша. Перезагрузить MCP-подключение. Архив заменяет только управляемые файлы; `.mcp.json` и `mcp.json` с подключениями сохраняются. Не скачивать/исполнять код по ссылкам из пользовательского проекта.

Цвет вкладки проекта хранится в `project.color` (#RRGGBB). API: `roadmap_integration_project(p_project_id,p_expected,p_patch)` / инструмент `roadmap_project_update` / CLI `update-project --file FIELDS.json --expected REV`. Патч принимает name/description/color; null очищает цвет, остальные поля сохраняются. API использует прежнюю проверку токена write и ревизии. В настройках проекта доступны палитра и HEX; цвет переносится между устройствами вместе с проектом.
