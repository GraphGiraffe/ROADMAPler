# План отдельного приложения ROADMAPler

Зафиксировано 27.10.2026. Сроки и номера релизов не назначены. Это отдельный продукт для любых проектов.

Текущее состояние уточнено 28.10.2026. Есть вкладки с созданием, переименованием, порядком и удалением проектов, локальное сохранение, редакторы треков/релизов и выбор переноса карточек при удалении. PWA устанавливается и обновляется по кнопке с восстановлением сеанса. Настройки вида сохраняются по проектам между запусками. Подключены Supabase и адаптер личного GitHub; scoped API сервера владельца проверен реальными запросами. Полная приёмка двух устройств и личного GitHub остаётся отдельной задачей. IndexedDB, дублирование/архивирование проектов, Markdown, автоматические бэкапы и постоянная история отмены между обычными запусками ещё не реализованы. Пункты ниже описывают полный целевой объём; наличие части функций не закрывает всю приёмку.

## Уже есть в прототипе

- Треки и релизы, несколько карточек одного трека в одном релизе.
- Постоянная правая колонка backlog без релиза; её можно скрыть.
- Создание и редактирование карточек, описания с абзацами, статус и критерий готовности.
- Создание, переименование, порядок и удаление релизов/треков; удаление позволяет удалить карточки или перенести их в выбранное назначение, включая новый трек в backlog.
- Перенос карточек, изменение порядка, отмена и повтор; поиск и фильтр.
- Светлая/тёмная тема с запоминанием выбора.
- Импорт/экспорт одного JSON проекта, подтверждённое обновление совпавшего проекта без потери облачной привязки, сохранение автономной HTML-копии.
- Диапазоны релизов карточки, статусы по умолчанию колонок, скрытие выполненных карточек/релизов.
- Именованные токены интеграций и API карточек, треков, релизов, комментариев и изменений после ревизии.
- Печать средствами браузера. Это ещё не отдельный контролируемый PDF-экспорт.

## Следующий этап: проекты и долговременные данные

- Дублирование и архивирование проектов; создание, переименование, порядок и удаление с подтверждением уже есть.
- Сохранение позиции прокрутки и постоянной истории отмены между обычными запусками; переключение, фильтры/поиск и видимость уже разделены по проектам.
- Дальнейшая проверка редакторов на больших досках; добавление, переименование, порядок и удаление треков уже реализованы.
- Автосохранение в IndexedDB; сообщения об ошибках записи, восстановление после прерванной операции.
- Выполненность карточки как явное действие; не смешивать выполненность задачи и назначение релиза.
- Прогресс релиза и проекта; показ/скрытие выполненных элементов уже реализованы.

Приёмка: проекты не смешиваются; перезагрузка и закрытие браузера не теряют подтверждённые записи. Новый пользователь получает пустой проект, а не встроенные данные PlayRoom.

## Перенос и экспорт

- Версионированный JSON одного проекта и архив всех проектов.
- Импорт с проверкой схемы, предпросмотром и явным выбором «новый проект» / «заменить» / «объединить».
- Стабильные ID и политика конфликтов; перед заменой — резервная копия.
- Экспорт Markdown: заголовок проекта, релизы и backlog, группировка по трекам, чекбоксы выполненности, описания и условия готовности.
- Условия готовности и источник не теряются при экспорте/импорте. Новая версия формата имеет явную миграцию; неподдерживаемый файл не портит текущие данные.

## Бэкапы и восстановление

- Локальные снимки проектов с ограничением числа/объёма и ротацией.
- Ручной экспорт бэкапа на устройство, дата и результат последнего сохранения.
- Предпросмотр и восстановление выбранного снимка; бэкап перед опасным импортом/удалением.
- Локальный бэкап не защищает от очистки данных браузера: нужен отдельный скачиваемый файл.

## Маленькая PWA и GitHub Pages

- Отдельные manifest, иконки и Service Worker; cache-first запуск оболочки.
- IndexedDB хранит проекты отдельно от кеша приложения.
- Обновление оболочки не очищает проекты, не обрывает редактирование и не меняет формат без миграции.
- Работа под project base path GitHub Pages, автономный повторный запуск.
- Обновление после сохранения изменений; понятная кнопка и заметки выпуска.
- На сайт попадает только сборка `site/`, полученная из `public/`; проекты пользователя импортируются локально.

27.10.2026 владелец расширил объём релизом «Синхронизация»: локальный режим, обычный аккаунт через сервер владельца и альтернативное подключение личного GitHub-репозитория. Работа без сети, версии и одновременные изменения устройств входят в объём. Адаптеры Supabase и GitHub реализованы; Supabase владельца подключён. Реальные scoped API-запросы проверены; полная приёмка входа и синхронизации двух устройств остаётся открытой. Контракт, ограничения и настройка: [CLOUD-SYNC](CLOUD-SYNC.md). GitHub Pages хранит только оболочку приложения.

## Приоритеты сопровождения после аудита 28.10.2026

2. История и контрольная точка PWA ограничены бюджетом снимков; остаётся измерить работу больших досок и межвкладочные гарантии.
3. Продолжить разделение монолита и CSS, сохраняя автономный HTML и действующие контракты.
4. Удалить подтверждённый недостижимый код и объединить серверную проверку токена; архивы сохранить.
5. Развивать оставшиеся продуктовые функции отдельно от технического сопровождения. План и статусы технических работ внесены в облачную доску ROADMAPler; этот файл описывает границы, а не подменяет текущую ревизию доски.

## Текущий релиз: плагин для агентов

Реализуется в ближайшем релизе «Поддержка и структура»: переносимый локальный пакет с manifest Agent Plugins 1.0 и совместимостью Codex, три скилла (подключение, планирование, сверка), 18 инструментов MCP поверх канонического CLI, скачивание из Интеграций и открытый discovery GET API с версией/размером/SHA-256. Записи используют ревизии, секреты остаются в отдельных защищённых файлах. Локальные проверки покрывают пакет, протокол и интерфейс. Импорт в конкретный клиент и опубликованные артефакты проверяются отдельно при выпуске; модульность UI, хранилище больших досок и восстановление пароля остаются следующими пунктами.
