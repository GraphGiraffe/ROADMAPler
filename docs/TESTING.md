# Локальные проверки ROADMAPler

Нужен Node.js 22+, для SQL — Python 3 и локальные инструменты PostgreSQL. Рабочая папка — корень репозитория. Все команды выполняются локально; workflow Pages не устанавливает dev-зависимости и не запускает тесты.

## Контракт формата

```sh
npm test
```

Только встроенные модули Node.js. `tests/project-format.test.mjs` загружает реальный `public/app/project-format.js` и проверяет `tests/fixtures/project-format.json`: версии 1/2, диапазоны, статусы, ID/title, служебные релизы, ссылки, неизвестные поля и неизменность входных данных. Отдельный случай запускает portable installer в чистом окружении. `tests/history.test.mjs` проверяет ограничения числа/размера снимков, непрерывность цепочки, приоритет redo и автономный установщик истории.

## Браузер

```sh
npm ci
npm run test:browser
```

Команда собирает `site/`, затем запускает тесты через собственный `playwright-core` из lockfile. Установленный Chrome/Chromium на Linux обнаруживается автоматически; другой путь задаётся `CHROME_PATH`. При отсутствии браузера: `npx playwright-core install chromium`. Сам браузер не входит в npm-пакет и не загружается при обычной сборке.

Проверяются активный и неактивный облачные проекты, сохранение ревизии/base и произвольных метаданных, отмена/повтор, перезагрузка, отказ записи, отмена импорта, создание независимой локальной копии, все отрицательные фикстуры до изменения библиотеки, автономный HTML и офлайн-перезагрузка PWA с новым модулем формата. Некорректная старая библиотека не перезаписывается и скачивается целиком для восстановления.

Каждый сценарий использует отдельный browser context. HTTP-сервер работает только на случайном порту loopback; облачный вход не выполняется, настоящие учётные данные и проекты не читаются. Обычные тесты блокируют Service Worker; отдельный PWA-сценарий явно разрешает его в собственном контексте.

История дополнительно проверяется после ротации 70 команд: undo/redo и новая ветка, восстановление PWA, крупный проект, облачные замены и импорт, независимость проектов, общий бюджет контрольной точки и отказ sessionStorage без потери данных. Автономный HTML проверяется с редактированием и отменой.

## PostgreSQL

```sh
npm run test:sql
```

`tests/sql/project_format.py` использует те же фикстуры, создаёт временный кластер и дважды применяет текущий `server/supabase.sql`. Пример Supabase Auth минимален и нужен только для разбора схемы; проверяется настоящий PostgreSQL-валидатор, не его копия на Python.

Нужны `initdb`, `pg_ctl`, `psql`, `pg_config`; `PG_BIN` позволяет выбрать другую установленную версию. Linux/macOS, запуск обычным пользователем. Кластер имеет отдельный временный Unix-сокет, TCP выключен, после проверки кластер останавливается и удаляется. Порт не занят в сети и рабочие серверы не затрагиваются.

## Границы набора

Это начальный постоянный набор, а не полный перенос всех прежних временных проверок. Он не доказывает приёмку настоящего аккаунта/двух устройств и не покрывает целиком токены, облачный протокол, жесты диапазонов, все размеры экранов или межвкладочные гонки. Последующие этапы расширяют набор вместе со своими контрактами. Ошибка окружения считается неуспешной проверкой, а не пропуском.
