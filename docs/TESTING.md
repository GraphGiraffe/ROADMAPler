# Локальные проверки ROADMAPler

Нужен Node.js 22+, для SQL — Python 3 и локальные инструменты PostgreSQL. Рабочая папка — корень репозитория. Все команды выполняются локально; workflow Pages не устанавливает dev-зависимости и не запускает тесты.

## Контракт формата

```sh
npm test
```

Модули контракта/истории используют только встроенные модули Node.js. Тесты пакета требуют также Python 3 (стандартный zipfile для независимого чтения ZIP). `tests/project-format.test.mjs` загружает реальный `public/app/project-format.js` и проверяет `tests/fixtures/project-format.json`: версии 1/2, диапазоны, статусы, ID/title, служебные релизы, ссылки, неизвестные поля и неизменность входных данных. Отдельный случай запускает portable installer в чистом окружении. `tests/history.test.mjs` проверяет ограничения числа/размера снимков, непрерывность цепочки, приоритет redo и автономный установщик истории.

## Браузер

```sh
npm ci
npm run test:browser
```

Команда собирает `site/`, затем запускает тесты через собственный `playwright-core` из lockfile. Установленный Chrome/Chromium на Linux обнаруживается автоматически; другой путь задаётся `CHROME_PATH`. При отсутствии браузера: `npx playwright-core install chromium`. Сам браузер не входит в npm-пакет и не загружается при обычной сборке.

Проверяются активный и неактивный облачные проекты, сохранение ревизии/base и произвольных метаданных, отмена/повтор, перезагрузка, отказ записи, отмена импорта, создание независимой локальной копии, все отрицательные фикстуры до изменения библиотеки, автономный HTML и офлайн-перезагрузка PWA с новым модулем формата. Некорректная старая библиотека не перезаписывается и скачивается целиком для восстановления.

Каждый сценарий использует отдельный browser context. HTTP-сервер работает только на случайном порту loopback; облачный вход не выполняется, настоящие учётные данные и проекты не читаются. Обычные тесты блокируют Service Worker; отдельный PWA-сценарий явно разрешает его в собственном контексте.

История дополнительно проверяется после ротации 70 команд: undo/redo и новая ветка, восстановление PWA, крупный проект, облачные замены и импорт, независимость проектов, общий бюджет контрольной точки и отказ sessionStorage без потери данных. Автономный HTML проверяется с редактированием и отменой.

## PostgreSQL

```sh
npm run test:sql
```

`tests/sql/project_format.py` использует те же фикстуры, создаёт временный кластер и дважды применяет текущий `server/supabase.sql`. Проверяется настоящий PostgreSQL-валидатор, не его копия на Python. Затем дважды применяются `server/integrations.sql` и `server/integration-api.sql`, в том числе поверх старого определения helper. `tests/sql/integration_auth.sql` вызывает полный, карточный, структурный API и дельты под ролями anon/authenticated: права read/write/delete, отсутствующий/неизвестный/просроченный/отозванный токен, ограничения проекта и владельца (включая одинаковый ID у двух владельцев), регистрация использования, конфликты ревизий и tombstone. Прямой доступ к таблице и helper запрещён. Минимальный Auth stub читает тестовый subject из настройки сессии; настоящая регистрация/почта этим не проверяются.

Нужны `initdb`, `pg_ctl`, `psql`, `pg_config`; `PG_BIN` позволяет выбрать другую установленную версию. Linux/macOS, запуск обычным пользователем. Кластер имеет отдельный временный Unix-сокет, TCP выключен, после проверки кластер останавливается и удаляется. Порт не занят в сети и рабочие серверы не затрагиваются.

## Границы набора

Это начальный постоянный набор, а не полный перенос всех прежних временных проверок. Он не доказывает приёмку настоящего аккаунта/двух устройств и не покрывает целиком токены, облачный протокол, жесты диапазонов, все размеры экранов или межвкладочные гонки. Последующие этапы расширяют набор вместе со своими контрактами. Ошибка окружения считается неуспешной проверкой, а не пропуском.

## Плагин агентов

`npm test` включает `tests/agent-plugin.test.mjs`: воспроизводимость архива, CRC/чистая распаковка независимым zipfile, manifest/совместимость/лицензии, три скилла, запуск MCP из распакованного пакета без зависимостей, discovery 18 инструментов, schemas и все маршруты к существующему CLI. Локальный HTTP fixture проверяет expected revision, пагинацию, явное удаление, запрет неизвестных полей, небезопасных credentials-файлов, редактирование секретов в ответах и однократный запрос при 409/401/403/410. Учётные данные синтетические. `npm run test:browser` сверяет API и web-ссылку, скачивает ZIP без аккаунта, проверяет размер/хеш, ошибку discovery и повтор. Эти проверки не доказывают импорт полного плагина в UI конкретной версии Codex или публикацию пакета; эти статусы нужно проверять отдельно.

## Восстановление пароля

Браузерный набор перехватывает все запросы к тестируемому Supabase-домену: настоящие письма и изменения аккаунтов не выполняются. Покрыты корректность почты/redirect, нейтральное сообщение, 429 и явный повтор, очистка URL до проверки пользователя, подтверждение нового пароля, несовпадение/длина, 503 без автоматического повтора, недействительные и неверного типа ссылки, поздний ответ после закрытия, неизменность проектов и сохранённого подключения другого пользователя. Токены и новый пароль не попадают в хранилища. Отдельный PWA-сценарий требует доступность recovery-модуля после офлайн-перезагрузки. Это не заменяет приёмку настоящего письма, allowlist redirect, SMTP/CAPTCHA и поведения email-ссылки на устройстве владельца.

## Разделение исходников и большие доски

`npm run test:browser` собирает HTML из manifest исходных единиц и CSS; прежние сценарии сохраняют проверку portable HTML и офлайн-PWA. Новые случаи проверяют одновременную попытку записи двух табов, запрет старого снимка после передачи владения, успешную запись после reload, независимость application scope, безопасный режим при отсутствии Web Locks, миграцию старых настроек и немедленную перезагрузку, просмотр разных проектов и независимые ключи настроек.

Измерительный сценарий использует 200 и 1000 синтетических карточек: десять input-событий, число перерисовок, записей вида, сериализаций/записей библиотеки и синхронное время обработки ввода. Результаты — tmp_files/board-performance-after.json; исходный замер — board-performance-before.json. Время ввода не является временем полной отрисовки: поиск намеренно отложен на 120 мс, запись настроек — на 200 мс. Не использовать эти цифры как гарантию FPS/скорости телефона или измерение всего JS heap. Тест проверяет численные операции, а не жёсткий порог миллисекунд. Режим ROADMAP_BENCH_BASELINE=1 нужен только для сравнительного измерения старой реализации и не является проходным критерием регрессий.

## Окно подключённого аккаунта

Браузерные регрессии воспроизводят сохранённую Supabase-сессию при скрытой форме входа: видимость обеих кнопок пароля, предзаполнение почты, прямую смену без logout, подтверждение/отмену выхода с сохранностью проектов и поздний refresh после подтверждённого выхода. Auth перехвачен синтетическим API: настоящие письма и пароли пользователей не изменяются. Мобильный/desktop скриншоты окна сохраняются в tmp_files/account-actions-*.png.
