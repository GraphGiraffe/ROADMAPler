# ROADMAPler · интеграции · 27.10.2026

Патч облачного прототипа: приложения и агенты могут читать и менять один выбранный облачный проект без пароля аккаунта ROADMAPler и без административного ключа Supabase.

## Что добавлено

- Меню → «Интеграции»: имя токена, проект, отдельные права чтения, изменения и удаления.
- Срок 7/30/90/365 дней, отзыв с подтверждением, последний успешный запрос.
- Секрет выдаётся сервером один раз. На сервере хранится SHA-256; полный секрет не попадает в список, библиотеку браузера или экспорт.
- Сервер проверяет проект, права, срок и отзыв через Supabase RPC. Прямая запись в закрытые таблицы запрещена.
- Общее изменение проекта для UI и интеграций: валидация, ожидаемая версия и история. Конфликт даёт 409 без автоматической перезаписи.
- CLI `integration-client.mjs` читает подключение из отдельного защищённого файла; поддерживает чтение, изменение и отдельное подтверждённое удаление.

## Как начать

1. Обновить PWA через меню приложения.
2. Войти в обычный аккаунт ROADMAPler; включить облачный режим нужного проекта и дождаться первой синхронизации.
3. Меню → «Интеграции»: выбрать проект, имя и права, создать токен.
4. Скачать файл подключения. Сохранить вне репозитория, например `~/.config/roadmapler/credentials.json`, с правами `600`.
5. Агенту передавать путь к файлу и ID проекта, не сам секрет в чате.

Право удаления по умолчанию выключено. Токены не распространяются на локальные проекты и личный GitHub. Секрет после закрытия окна не восстанавливается: при потере нужно создать новый токен и отозвать старый.

## Проверки и границы

Владелец применил серверное SQL-обновление. На настоящем Supabase проверены наличие новых RPC, запрет анонимного управления токенами, отказ доступа без токена и CORS для заголовка `X-ROADMAPler-Token`.

Локально проверены реальные SQL-функции на отдельном PostgreSQL: собственник и проект, независимые права, хеш вместо секрета, срок, отзыв, последнее использование, CAS и неверные данные. Chrome и CLI работали с этими SQL-функциями через локальный HTTP-слой: проверены создание/скачивание, права файла, запись, конфликт, чужой проект, запрет удаления, отзыв, очистка закрытием/Escape и отсутствие секрета в storage и HTML-экспорте. Сборка, синтаксические проверки и git diff --check прошли локально.

Авторизация локального HTTP-слоя имитируется. Настоящий токен интеграции на развёрнутом Supabase ещё не создан и не проверен; полный внешний сценарий ожидает токен для тестового проекта. Ограничения исходного облачного прототипа, включая настройку SMTP и отсутствие восстановления пароля в интерфейсе, сохраняются. GitHub Actions используется только для одной сборки и публикации Pages.
